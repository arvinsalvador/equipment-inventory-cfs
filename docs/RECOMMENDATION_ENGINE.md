# Recommendation Engine

## Architecture

Maintenance recommendations are persisted in `maintenance_recommendations` and generated by `App\Services\MaintenanceRecommendationEngine`. The engine is rule-based and explainable; it does not call external AI APIs or machine-learning services.

The engine exposes:

- `generateForAllEquipment()` for a full eligible-equipment scan.
- `generateForEquipment(Equipment $equipment)` for a single-equipment scan.

Refresh results include equipment scanned, new recommendations, updated recommendations, unchanged recommendations, skipped equipment, and errors.

## Rule List and Fields

### Overdue Maintenance

Rule key: `overdue_maintenance`

Triggers when `equipment.next_maintenance_date` is before today.

It does not require an active maintenance schedule. A populated old `last_maintenance_date` alone is not sufficient; the engine requires `next_maintenance_date` for overdue and due-soon maintenance rules.

### Due Soon

Rule key: `due_soon`

Triggers when `equipment.next_maintenance_date` is today through seven days from today, inclusive.

This is mutually exclusive with overdue maintenance because overdue dates are evaluated first.

### Defective Without Work Order

Rule key: `defective_without_work_order`

Triggers when `equipment.condition` is `Defective` and the equipment has no open work order through `openWorkOrders()`.

### Repeated Repairs

Rule key: `repeated_repairs`

Triggers when the equipment has at least three completed work orders with `completed_at` within the last 90 days.

### No Maintenance History

Rule key: `no_maintenance_history`

Triggers when the equipment has no completed maintenance schedules and no completed work orders.

### Warranty Expiring

Rule key: `expiring_warranty`

Triggers when `equipment.warranty_expiration_date` is today through 30 days from today, inclusive.

Already expired warranties do not currently trigger this rule unless the date is today. This threshold is unchanged by the refresh enhancement.

### Missing Evidence

Rule key: `beyond_repair_evidence_incomplete`

Triggers when `equipment.condition` is `Beyond repair` or when a beyond-repair work order has fewer than two beyond-repair evidence records.

### Completed Without After Evidence

Rule key: `completed_without_after_evidence`

Triggers when a completed work order has no `After maintenance` evidence.

## Triggers

Current generation mechanisms:

- Manual administrator action: `Refresh Recommendations` on the Recommendations list page.
- Optional single-equipment action: `Refresh Recommendations` on the Equipment view page.
- Artisan command: `recommendations:refresh`.
- Backward-compatible Artisan command: `maintenance:generate-recommendations`.
- Daily scheduler entry: `recommendations:refresh` at 01:30.
- Seeders may invoke the engine to create demo recommendation data.

Automatic model-event refresh on equipment create/update, schedules, work orders, or evidence remains deferred because creating recommendations during ordinary saves would change broad test and workflow behavior. Use the single-equipment refresh action or scheduled command until campus policy confirms which model changes should generate recommendations immediately.

## Scheduler Cron

On Bluehost or similar shared hosting, configure Laravel's scheduler cron to run every minute:

```bash
php /full/path/to/artisan schedule:run
```

Do not hardcode the hosting path in application code.

## Duplicate Prevention

The engine keeps at most one active recommendation per equipment and rule key. Active statuses are:

- `Open`
- `Reviewed`
- `Approved`

If an active recommendation exists and calculated details changed, it is updated. If details are unchanged, it is counted as unchanged. Resolved and dismissed records are preserved as history and are not modified by refresh.

## Eligible Equipment

The refresh scans equipment unless it is archived or has operational status `Disposed`. Beyond-repair equipment is still eligible because it may require evidence, replacement, or disposal follow-up.

## Recommendation Lifecycle

Recommendations are generated as `Open` with action status `Pending`. Administrators review, approve, resolve, dismiss, reject, execute, or cancel actions through the existing Filament workflow. Approval can create a linked maintenance request for actionable rules. Work order and schedule outcomes continue to update linked recommendation state through the existing maintenance workflow.

## Troubleshooting

### Equipment has an old last maintenance date but no recommendation

`last_maintenance_date` alone does not trigger overdue or due-soon recommendations. Set `next_maintenance_date` to a past date for overdue maintenance or within the next seven days for due-soon maintenance.

Also verify the equipment is not archived and its operational status is not `Disposed`.

### Equipment has an expired warranty but no recommendation

The current warranty rule only checks dates from today through the next 30 days. A warranty that expired before today is outside the current warning window.

### Repeated refreshes create no new records

That is expected when the active recommendation already exists. Check the unchanged count in the refresh summary.
