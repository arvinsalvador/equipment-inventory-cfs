# Maintenance Workflow Audit

## Current Workflow Found

The maintenance workflow uses Filament actions on Recommendations, Maintenance Requests, Maintenance Schedules, Work Orders, and Work Order Evidence.

- AI recommendations are generated with a rule key, risk level, suggested action type, recommendation status, and action status.
- Approving an actionable recommendation creates one linked maintenance request.
- Maintenance requests are reviewed, approved or rejected, and approved requests can be converted to one work order.
- Maintenance schedules are manually created or generated by recommendation execution, display due/overdue state from scheduled dates, and generate the next recurring schedule when completed.
- Work orders move through available, assigned, accepted, in progress, for verification, completed, beyond repair, reopened, and cancelled states.
- Work order evidence is attached through the work order evidence relation manager and is required for completion and beyond-repair actions.

## Final Workflow After Fixes

- Recommendation approval creates and links a maintenance request for actionable rules.
- Maintenance request conversion creates and links a work order.
- Recommendations now show the linked work order directly or through the linked maintenance request.
- Work order completion, verification, beyond-repair, reopen, and cancellation now reflect back to recommendations linked either directly to the work order or indirectly through the maintenance request.
- Recommendation Execute is blocked while linked maintenance work is unfinished, preventing duplicate downstream records.

## Recommendation Action Behavior

- Mark Reviewed sets `status`, `reviewed_by`, and `reviewed_at`.
- Mark Resolved sets `status`, `resolved_by`, and `resolved_at`.
- Dismiss sets dismissed status and resolution fields without creating downstream records.
- Approve Action sets recommendation and action approval state, creates one maintenance request when actionable, and links it through `linked_maintenance_request_id`.
- Execute Action no longer bypasses unfinished linked maintenance work. It only marks the recommendation executed/resolved when linked work is completed or beyond repair.
- Reject Action requires notes and sets action status to rejected.
- Cancel Action requires notes and is blocked once downstream maintenance records exist.

## Maintenance Request Action Behavior

- Approve sets the request to approved with review fields.
- Reject stores rejection fields and creates no work order.
- Convert to Work Order creates one linked work order and marks the request converted.
- Duplicate conversion returns the existing work order instead of creating another.
- If the request came from a recommendation, conversion also links the work order back to the recommendation.
- Cancel is allowed only before approval/conversion/rejection/cancellation.

## Maintenance Schedule Behavior

- Due, due-today, and overdue states are derived from `scheduled_date` for incomplete schedules.
- Completion sets completion fields, updates equipment maintenance dates, resolves linked recommendations, and generates the next recurring schedule once.
- Reschedule and cancel are blocked after completion or cancellation.
- No automatic request or work order is created on page load.

## Work Order Action Behavior

- Assign stores assignment fields and sets assigned status.
- Accept and Start move the work order through accepted and in-progress states.
- Evidence upload stores work-order, equipment, type, image, uploader, and upload timestamp.
- Submit for Verification stores work details and sets for-verification status.
- Complete requires after-maintenance evidence and final work details, updates equipment final state, and resolves linked recommendations.
- Verify enforces evidence and self-verification rules, stores verifier fields, and resolves linked recommendations.
- Beyond Repair requires findings, reason, recommended action, and two beyond-repair evidence records; it updates equipment state and resolves linked recommendations.
- Reopen and Cancel reflect back to linked recommendations.

## Status Map

- Recommendation status: Open, Reviewed, Approved, Resolved, Dismissed.
- Recommendation action status: Pending, Approved, Executed, Rejected, Cancelled.
- Maintenance request status: Submitted, For review, Approved, Converted, Rejected, Cancelled.
- Maintenance schedule status: Upcoming, Due soon, Due today, Overdue, In progress, Completed, Rescheduled, Cancelled.
- Work order status: Submitted, For review, Approved, Available, Assigned, Accepted, In progress, On hold, Awaiting parts, For verification, Completed, Beyond repair, Reopened, Rejected, Cancelled.

## Relationship And Linkage Map

- Recommendation to maintenance request: `maintenance_recommendations.linked_maintenance_request_id`.
- Recommendation to work order: `maintenance_recommendations.linked_work_order_id`.
- Recommendation to schedule: `maintenance_recommendations.linked_maintenance_schedule_id`.
- Maintenance request to work order: `work_orders.maintenance_request_id`.
- Work order to evidence: `work_order_evidences.work_order_id`.
- Recommendation work-order display resolves direct `linkedWorkOrder` first, then `linkedMaintenanceRequest.latestWorkOrder`.

## Duplicate Prevention Rules

- One maintenance request per recommendation.
- One work order per maintenance request.
- One next recurring schedule per completed schedule.
- Completed and cancelled schedules cannot be completed again.
- Closed work orders are hidden from unsafe repeat actions.
- Recommendation Execute is blocked while linked maintenance work is not complete.

## Known Limitations

- Maintenance schedules do not currently expose a separate create-request or create-work-order action.
- Maintenance requests do not have completed/resolved statuses in the current model; conversion to work order is the terminal successful request state.
- Manual browser validation is still needed for notifications, action visibility by role, and mobile/offline workflows.

## Manual Validation Checklist

- Approve an actionable recommendation and confirm one maintenance request is created.
- Approve and convert the request and confirm one work order is created.
- Reopen the recommendation detail and confirm the work order number, title, status, assignee, and verification date render.
- Complete or verify the work order and confirm the recommendation becomes executed/resolved.
- Try duplicate approval and conversion clicks and confirm no duplicate records are created.
- Validate evidence upload, completion, verification, beyond-repair, cancellation, and reopen actions in a browser for administrator, staff, and technician roles.
